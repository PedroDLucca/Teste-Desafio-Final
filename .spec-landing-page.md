# Spec — Landing Page "Flicker of Sanity"

## Problem Statement

Como visitante do site do jogo Flicker of Sanity, não existe uma página que apresente o conceito do jogo, suas mecânicas únicas e convide o usuário a criar uma conta e jogar. Sem essa vitrine, não há como atrair novos jogadores nem comunicar a proposta de valor do jogo cooperativo de navegador.

## Solution

Criar uma landing page single-scroll com 7 seções (Header fixo, Hero, Sobre o Jogo, Features, Como Jogar, Call to Action e Footer) que apresente a atmosfera de suspense do jogo, destaque suas mecânicas cooperativas e direcione o usuário para a criação de conta. A página será totalmente responsiva, acessível (WCAG 2.1 AA) e otimizada para performance (Lighthouse Performance ≥ 80).

## User Stories

1. Como visitante do site, quero ver uma primeira dobra impactante com o nome do jogo e uma frase de efeito, para que eu entenda imediatamente a proposta do jogo
2. Como visitante, quero ver um botão "Jogar Agora" visível no header e em múltiplas seções, para que eu possa acessar a página de cadastro rapidamente
3. Como visitante, quero navegar entre as seções da página através de links no header, para que eu encontre informações específicas sem rolar manualmente
4. Como visitante em dispositivo móvel, quero um menu hamburger que reveja os links de navegação, para que eu possa navegar confortavelmente em telas pequenas
5. Como visitante, quero ler a história e premissa do jogo na seção "Sobre o Jogo", para que eu entenda o contexto e me interesse em jogar
6. Como visitante, quero ver cards com as mecânicas principais do jogo (tabuleiro dinâmico, fog of war, monstros, minigames, cooperação, tempo real), para que eu entenda o que torna o jogo único
7. Como visitante, quero ver um passo a passo simplificado de como jogar (criar conta → criar sala → explorar → fugir), para que eu entenda o fluxo antes de me comprometer
8. Como visitante, quero ver uma seção final de convite com botão "Jogar Agora", para que eu tenha uma última chance de conversão ao final da página
9. Como visitante, quero que o header mude de aparência ao rolar a página (transparente → sólido), para que eu saiba em que ponto da página estou
10. Como visitante, quero que a página carregue em menos de 3 segundos, para que eu não desista antes de ver o conteúdo
11. Como visitante que usa teclado ou leitor de tela, quero que a página seja acessível (WCAG 2.1 AA), para que eu possa consumir todo o conteúdo
12. Como visitante, quero que o layout se adapte corretamente em diferentes tamanhos de tela (320px, 768px, 1024px, 1440px), para que eu tenha uma boa experiência em qualquer dispositivo
13. Como visitante, quero ver badges destacando "Cooperativo", "4 Jogadores", "Tempo Real", "Navegador" na seção Sobre, para que eu entenda rapidamente o formato do jogo
14. Como visitante curioso, quero ver links para "Regras" e "Suporte" no header e footer, para que eu saiba onde encontrar mais informações (rotas futuras)
15. Como visitante, quero ver o footer com links úteis, créditos e redes sociais, para que eu tenha acesso a informações legais e de contato

## Implementation Decisions

### D01 — Build e Stack
- **Vite + React 18 + TypeScript** como base do projeto em `frontend/web/`
- **Tailwind CSS** como framework de estilização, configurado com paleta custom `brand.*` mapeada das 6 cores da spec:
  - `brand.black` (#0A0A0F) — background principal
  - `brand.gray` (#1A1A2E) — cards, seções alternadas
  - `brand.purple` (#16213E) — acentos, hover states
  - `brand.flame` (#E2B857) — CTAs, destaques
  - `brand.white` (#E8E8E8) — texto principal
  - `brand.muted` (#A0A0B0) — texto secundário

### D02 — Tipografia
- **Google Fonts**: Cinzel (títulos, bold) + Inter (corpo, regular)
- Configuradas via `@import` no CSS global com `font-display: swap` para performance
- Mapeadas no Tailwind como `font-heading` (Cinzel) e `font-body` (Inter)

### D03 — Roteamento
- Sem React Router nesta iteração. Links de navegação usam `<a href="#secao">` com âncoras internas
- Links para rotas futuras (`/regras`, `/suporte`, `/login`, `/cadastro`) usam `<a href="/rota">` simples
- Estrutura preparada para adicionar React Router quando as rotas forem implementadas

### D04 — Animações
- CSS puro com `@keyframes`, `transition` e `IntersectionObserver` para animações triggeradas por scroll
- Apenas `transform` e `opacity` para animações (GPU-accelerated, conforme RNF05)
- Sem bibliotecas de animação externas

### D05 — Ícones e SVGs
- SVGs inline como JSX nos componentes, estilizados com Tailwind classes
- Sem dependência de biblioteca de ícones nesta iteração
- Ícones necessários: hamburger menu, 6 features (tabuleiro, fog of war, monstro, engrenagem, grupo, relógio)

### D06 — Hero Background
- Gradiente animado escuro como placeholder (preto → roxo escuro → preto) usando CSS `@keyframes`
- Sem vídeo nesta iteração — estrutura preparada para substituir por `<video>` quando o asset estiver disponível
- Fallback de imagem estática para mobile/baixa conexão (RNF01)

### D07 — Arquitetura de Componentes
```
main.tsx → App.tsx → LandingPage.tsx
  ├── Header (fixo, muda de estado ao scroll)
  ├── Hero (gradiente animado + título + tagline + CTAs)
  ├── About (narrativa + imagem placeholder + badges)
  ├── Features (grid responsivo de FeatureCards)
  │   └── FeatureCard (ícone SVG inline + título + descrição)
  ├── HowToPlay (timeline de Steps)
  │   └── Step (número + título + descrição)
  ├── CallToAction (título + subtítulo + botão)
  └── Footer (logo + links + créditos)
```

### D08 — Hook de Scroll
- `useScrollPosition` em `src/hooks/` — hook reutilizável com threshold configurável (default: 50px)
- Retorna boolean `isScrolled` para controle de estado do header

### D09 — Conteúdo Textual
- Todo o conteúdo (títulos, descrições, taglines, badges) centralizado em `src/content/landing.ts`
- Objeto tipado TypeScript, preparado para migração futura para i18n
- Sem `react-i18next` nesta iteração

### D10 — Scroll Suave
- `scroll-behavior: smooth` no CSS global (`html`)
- Sem implementação JS customizada para smooth scroll

### D11 — Responsividade
- Breakpoints: 320px (mobile), 768px (tablet), 1024px (desktop pequeno), 1440px (desktop)
- Grid de features: 1 coluna (mobile), 2 colunas (tablet), 3 colunas (desktop)
- Menu hamburger ativo abaixo de 768px

### D12 — Acessibilidade
- Alt text em todas as imagens
- ARIA labels em botões e links sem texto visível (hamburger)
- Navegação por teclado funcional (tab order, focus visible)
- Contraste mínimo AA entre texto e background

### D13 — SEO
- Meta tags: title, description, Open Graph
- Favicon placeholder
- Semantic HTML (`header`, `main`, `section`, `footer`, `nav`)

## Testing Decisions

### O que testar
- **Comportamento externo apenas**: interações do usuário com a página, não detalhes de implementação
- **Responsividade**: layout rendering nos breakpoints definidos (320px, 768px, 1024px, 1440px)
- **Navegação por âncora**: ao clicar em "Sobre", a página scrolla até a seção "Sobre o Jogo"
- **Header state change**: após 50px de scroll, header muda de transparente para sólido com sombra
- **Menu mobile**: ao clicar no hamburger, menu abre; ao clicar novamente, fecha
- **CTA redirects**: botões "Jogar Agora" apontam para `/login` ou `/cadastro`
- **Acessibilidade**: elementos com aria-labels, alt text, navegação por teclado

### O que NÃO testar
- Estilos visuais específicos (cores exatas, tamanhos de fonte) — isso é design, não comportamento
- Animações — testar via Lighthouse, não unit tests
- Performance numérica — testar via Lighthouse CI, não testes unitários

### Módulos testados
- `useScrollPosition` hook — retorna `true` após threshold, `false` antes
- `Header` — estado visual muda conforme scroll
- `LandingPage` — todos os componentes renderizam, links de navegação funcionam

### Prior art
- Não há testes existentes no repositório (greenfield). Estes serão os primeiros testes do projeto.
- Framework de teste a definir no scaffold do Vite (Vitest + React Testing Library recomendado).

## Out of Scope

- **Página de Login/Cadastro** — os CTAs apontam para rotas que não existem ainda
- **Página de Regras** — link futuro, não implementado
- **Página de Suporte** — link futuro, não implementado
- **Termos de Uso / Política de Privacidade** — links futuros no footer
- **Vídeo/trailer no Hero** — placeholder de gradiente animado; vídeo será adicionado quando o asset existir
- **Imagens/arte conceitual** — placeholders; assets reais serão integrados depois
- **Autenticação de usuário** — header não exibe nome do usuário logado nesta iteração
- **Indicador social** ("X jogadores online") — opcional, fora do escopo
- **i18n/internacionalização** — estrutura preparada, mas não implementada
- **React Router** — adicionado quando as rotas forem implementadas
- **Backend/API** — nenhuma integração com backend nesta iteração

## Further Notes

- Esta é a **primeira feature de código** do projeto. O scaffold do Vite + React + TypeScript + Tailwind será criado como parte desta implementação.
- O ADR-0001 (Estrutura de Pastas do Monorepo) define que `frontend/web/` é o app React + Vite + Three.js. Nesta iteração, apenas a landing page é implementada — o Three.js será usado nas páginas de jogo futuras.
- O `gh` CLI não está instalado no ambiente local. A publicação desta spec no GitHub Issues depende de instalação prévia do `gh` ou publicação manual via interface web.
- Labels recomendadas para a issue: `pronto-para-agente`, `melhoria`, `frontend`.
